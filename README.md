# PyLearn — учебная платформа для изучения Python

Веб-приложение на Flask для обучения языку Python с тремя ролями:

- **Ученик** — проходит курсы: читает уроки (markdown), проходит тесты и решает
  практические задачи по коду с автоматической проверкой, видит свой прогресс.
- **Учитель** — создаёт курсы, уроки, задания (тесты с вариантами ответов или
  задачи по коду с тест-кейсами), видит список учеников и их прогресс, решения.
- **Админ** — управляет пользователями (роли, активация/деактивация), создаёт
  учителей, модерирует список курсов.

Проект сделан в рамках учебного задания (производственная практика), поэтому
сознательно не содержит лишней инфраструктуры, характерной для коммерческих
проектов (нет микросервисов, очередей, внешних API, деплой-пайплайнов и т.п.).
Вместо этого сделан акцент на том, чтобы то, что есть, — работало корректно.

## Стек технологий

- Python 3.10+
- Flask, Flask-SQLAlchemy, Flask-Login, Flask-WTF (CSRF-защита форм)
- SQLite (файл `instance/app.db`, создаётся автоматически)
- Bootstrap 5 (через CDN) для оформления
- Markdown — для отображения содержимого уроков

## Установка и запуск (Windows / PowerShell)

```powershell
git clone <URL_репозитория>
cd python_edu_platform
python -m venv venv
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt

# Создать таблицы БД
flask --app run init-db

# Создать администратора (запросит логин/email/пароль)
flask --app run create-admin

# (необязательно) наполнить демо-данными: учитель + курс + уроки + задания
flask --app run seed-demo

# Запустить сервер разработки
python run.py
```

Приложение будет доступно на http://127.0.0.1:5000

На Linux/macOS команды активации окружения отличаются (`source venv/bin/activate`),
остальные шаги идентичны.

Файл базы данных (`instance/app.db`) и виртуальное окружение (`venv/`) не входят
в репозиторий (см. `.gitignore`) — они создаются локально командами выше и
уникальны для каждой установки.

### Переменные окружения (необязательно)

По умолчанию используется тестовый `SECRET_KEY` из `config.py` — этого
достаточно для локального запуска/защиты практики. Для реального
развёртывания рекомендуется задать свой ключ:

```powershell
$env:SECRET_KEY = "свой-случайный-секретный-ключ"
```

## Роли и доступ

- Регистрация через `/auth/register` создаёт пользователя с ролью **ученик**.
- Роль **учитель** назначается только администратором (раздел «Пользователи»
  → «Создать учителя», либо изменением роли существующего пользователя).
- Первый администратор создаётся один раз командой `flask --app run create-admin`.

### Демо-доступы

Команда `flask --app run seed-demo` создаёт учебные тестовые данные — это
**не секретные production-данные**, а удобный набор для быстрой проверки
и защиты проекта:

- Учитель: `teacher_demo` / `teacher123` — курс «Python для начинающих» с 5 уроками.

Администратора демо-скрипт не создаёт — его нужно один раз создать самому
командой `flask --app run create-admin` (см. выше), указав любой логин/пароль.

## Как это работает

1. Учитель создаёт курс → добавляет в него уроки (текст с поддержкой Markdown,
   удобно для примеров кода) → в каждом уроке создаёт задания двух типов:
   - **Тест** — вопрос с 2–4 вариантами ответа и одним правильным;
   - **Код** — текстовое условие + набор тест-кейсов (вход/ожидаемый вывод).
2. Ученик записывается на курс из каталога, проходит уроки по порядку,
   отвечает на тесты (проверяются мгновенно) и решает задачи по коду.
3. Код ученика выполняется в отдельном процессе Python (`python -I`) с
   ограничением по времени и сверяется по всем тест-кейсам задания.
   Задание засчитывается, если пройдены все тест-кейсы.
4. Учитель видит прогресс каждого ученика по курсу и может открыть любое
   отправленное решение (для кода — построчный разбор по тест-кейсам).

## Важное ограничение (сознательно, в рамках учебного проекта)

Проверка кода учеников выполняется в отдельном процессе с таймаутом и в
изолированном режиме интерпретатора (`-I`), но это **не** полноценная
песочница (Docker/gVisor и т.п.). Для закрытого учебного окружения такой
подход достаточен, но использовать проект как публичный сервис для
выполнения произвольного кода от анонимных пользователей не стоит.
